# Задание 1. Анализ и планирование


### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут:
  1) удалённо включать/выключать отопление в своих домах через веб-интерфейс
  2) настраивать температуру в своих домах через веб-интерфейс
- Система поддерживает:
  1) управление отоплением через датчики
  2) настройку температуры через датчики

**Мониторинг температуры:**

- Пользователи могут:
  1) просматривать текущую температуру в своих домах через веб-интерфейс
- Система поддерживает:
  1) получение данных о температуре с датчиков, установленных в домах

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Java
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения
- Взаимодействие: Синхронное, запросы обрабатываются последовательно
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям
- Развёртывание: Требует остановки всего приложения

### 3. Определение доменов и границы контекстов

В монолитном приложении можно выделить следующие домены:

- Домен: климат-контроль
  - поддомен: система отопления
    - контекст: включение/выключение отопления
  - поддомен: терморегуляция
    - контекст: настройка температуры

- Домен: интеграция устройств
  - поддомен: подключение устройств
    - контекст: подключение датчиков отопления 
    - контекст: подключение датчиков температуры

- Домен: мониторинг устройств
  - поддомен: мониторинг температуры
    - контекст: получение данных о температуре

В системе, которую необходимо создать можно выделить следующие домены:

- Домен: управление климатом
  - поддомен: система отопления
    - контекст: включение/выключение отопления
  - поддомен: терморегуляция
    - контекст: настройка температуры

- Домен: освещение
  - поддомен: управление светом
    - контекст: включать/выключать свет

- Домен: безопасность
  - поддомен: управление воротами
    - контекст: запирать/отпирать автоматические ворота
  - поддомен: наблюдение за домом
    - контекст: работа с камерами

- Домен: интеграция устройств
  - поддомен: подключение устройств
    - контекст: подключение внедренных устройств (датчиков отопления, температуры, света и т.д.)
    - контекст: обнаружение новых устройств
  - поддомен: обслуживание устройств
    - контекст: оплата подписки на систему

- Домен: автоматизация устройств
  - поддомен: управление сценариями
    - контекст: программирование работы устройств пользователем

- Домен: мониторинг устройств
  - поддомен: просмотр температуры
    - контекст: получение данных о температуре
  - поддомен: просмотр состояния устройств
    - контекст: отображение статуса работы устройств
    - контекст: энергопотребление устройств
  - поддомен: управление уведомлениями
    - контекст: уведомление пользователей о неисправностях

### **4. Проблемы монолитного решения**

Компания «Тёплый дом» хочет перейти к модели SaaS с самообслуживанием, но текущая архитектура не позволяет:
- Быстро добавлять новые функции (например, управление освещением требует изменений в монолите)
- Масштабироваться (100 клиентов – предел для текущей системы)
- Обеспечить отказоустойчивость (падение сервера = отключение всех функций)
- Поддерживать разные устройства (нет гибкости для интеграции с партнёрскими решениями)

Вывод:
Текущий монолит мешает развитию бизнеса. Необходим переход на микросервисную архитектуру, чтобы:
- Разделить систему на независимые компоненты
- Обеспечить масштабируемость и отказоустойчивость
- Упростить добавление новых функций
- Дать пользователям возможность самостоятельного управления устройствами (их подключением и настройкой)
